# Lab 4 Test Plan & Traceability Matrix

## 1. Test Strategy & Methodology
Sprint 4 follows **Specification-Driven Development (Spec DD)**, **Test-Driven Development (Test DD / TDD)**, and systematic end-to-end regression hardening.

### 1.1 Required Test Types & Layers
In accordance with Section 10 of the Sprint 4 handout (`SE+Lab+4.pdf`), the test plan explicitly covers all ten required testing types across their authentic operational layers (93 unique Test IDs total):
1.  **Unit Tests (3 tests):** Pure in-memory calculation helpers, date boundary math, and dashboard queue aggregation algorithms (`DASH-02`, `DASH-07`, `DASH-08`).
2.  **API / Integration Tests (33 tests):** Supertest HTTP assertions verifying endpoints, payload validation, atomic conditional updates (CAS), idempotency keys, and health check probes (`ACT-01`–`ACT-07b` [8], `CON-01`–`CON-08` [8], `IDEMP-01`–`IDEMP-08` [8], `DASH-01`, `DASH-03`–`DASH-06`, `DASH-09`, `DASH-10`, `DASH-12` [8], `REG-03` [1]).
3.  **UI Component Tests (13 tests):** React Testing Library tests verifying rendering, user interactions, form validation, error preservation on 409 conflict, and state handling (`UI-ACT-01`–`UI-ACT-05`, `UI-WF-01`–`UI-WF-03`, `UI-DASH-01`–`UI-DASH-05`).
4.  **UI Style Tests (3 tests):** Programmatic inspection of Zen Green CSS tokens, badge color classes, modal keyboard focus trapping, Escape key dismiss, and ARIA attributes (`UI-STY-01`, `UI-ACC-01`, `UI-ACC-02`).
5.  **Responsive Tests (1 test):** Verification of layouts and interactions across Desktop (1200px), Tablet (800px), and Mobile (400px) viewports without horizontal clipping (`E2E-05`).
6.  **Authorization Tests (6 tests):** Explicit verification of the Authorization Matrix, 401 unauthenticated, 403 forbidden, and 404 non-enumeration policies (`ACT-08`–`ACT-12`, `DASH-11`).
7.  **Workflow Tests (25 tests):** Permitted status transitions across the 13-row matrix (including outgoing transitions from `Reopened`), Resolution Gate enforcement, comment-driven auto-transitions, and advisory resolution behavior (`WF-01`–`WF-10`, `WF-10b`, `WF-11`, `WF-12`, `WF-13a`–`WF-13c`, `WF-14` [17 tests] plus `CMT-01`–`CMT-08` [8 tests]).
8.  **Migration / Regression Tests (4 tests):** Verification of database schema alterations, audit retention (`onDelete: Restrict`), legacy `resolvedAt = NULL` backfill behavior, and full historical regression suites (`MIG-01`, `MIG-02`, `REG-01`, `REG-02`).
9.  **Performance-Smoke Tests (1 test):** Latency benchmarks ensuring dashboard queries and ticket detail loads complete within target thresholds (< 500ms) with 100+ seeded tickets (`SMK-01`).
10. **End-to-End (E2E) Tests (4 tests):** Multi-role Playwright browser automation simulating complete service desk journeys (`E2E-01`–`E2E-04`).

**Total Unique Test IDs: 3 + 33 + 13 + 3 + 1 + 6 + 25 + 4 + 1 + 4 = 93 Unique Tests.**

### 1.2 Execution Status Legend & Summary
*   **`Planned (Not Run)`** (90 tests): Test specification defined; implementation and execution deferred to development phase. (All new Lab 4 tests start in this state).
*   **`Regression (Verified in Release)`** (1 test): Existing suite verified passing during release verification (`REG-01`).
*   **`Verified (Passed)`** (2 tests): Test has been actually executed during baseline audit with passing evidence (`REG-02` [53/53 client unit tests], `REG-03` [1/1 health check probe]).

**Total Tests Reconciled: 90 Planned (Not Run) + 1 Regression (Verified in Release) + 2 Verified (Passed) = 93 Total.**

## 3. Test Safety, Database Isolation & Execution Rules
1.  **Isolation:** Integration tests executing against the database must generate records with unique timestamps or random prefixes (e.g. `test-act-${Date.now()}@example.com`).
2.  **Teardown & Referential Cleanup Order:** Integration tests must clean up test-created entities in strict reverse dependency order respecting foreign-key constraints and `onDelete: Restrict`:
    1.  `IdempotencyKey` records (foreign keys to `Ticket`, `User`).
    2.  `ActionTaken` records (foreign keys to `Ticket` and `User` with `onDelete: Restrict`; must be deleted before the associated Ticket or User).
    3.  `PublicComment`, `InternalNote`, and `Attachment` records (foreign keys to `Ticket` and `User`).
    4.  `Ticket` records (foreign keys to `User`, `Category`, `RelatedSystem`).
    5.  `Session` records (foreign key to `User`).
    6.  `User` principal records.
    Tests must never attempt to delete a `Ticket` or `User` while child `ActionTaken` records exist.
3.  **No Schema Resets in Tests:** Tests must never run `prisma migrate reset` or drop tables during test execution.
4.  **Mocked Unit Tests:** Frontend tests in `client/tests/lab-04/` must mock `fetch` using `vi.fn()` or `vi.stubGlobal('fetch', ...)` and must never attempt to contact a live backend server.
5.  **E2E Separation:** Playwright test suites must run with isolated user logins and avoid sharing test records across parallel workers.
6.  **Truth in Reporting:** No test is ever reported as `Passed` without concrete execution output and timestamps. All unexecuted Lab 4 tests remain marked as `Planned (Not Run)`.
